## Quality and operational limits

- Ten probes were declared before running retrieval and target five known development articles. They test retrieval of source material, not correctness of generated answers, broad recall, or unseen query performance. The first broad AI-governance question may have other relevant articles; expected-ID rank is only one relevance judgment.
- HNSW is approximate nearest-neighbor retrieval. Multiple chunks from one article can occupy top-k. Reported distinct-article ranks are deduplicated from the first ten returned chunks; this does not guarantee a global top-five article ranking.
- No answerability threshold is calibrated. Search may return an unrelated nearest neighbor for unsupported questions; grounded answers and refusal are the next stage. Distances are not confidence probabilities.
- Financial/entity extraction limitations remain. Complete location/company lists and repeated-investor aggregation need full record/body checks and distinct event/round handling, not vector top-k alone.
- Search verifies every accepted record/raw input and persisted chunk/vector before retrieval. This is practical for 81 articles but adds latency; a larger concurrent service needs validated snapshots/generations and a different serving design. Current tools serialize on one shared project lock.
- Corpus/model/index artifacts remain local and ignored. A clean-machine setup, publication/sharing review, final eight query evaluations, repository and demo remain unfinished.
